# Art direction (Phase 3A)

Locked specification for the pixel-art visual overhaul. Everything under
`assets/pixel/` is generated by `tools/generate_pixel_assets.gd` and is
placeholder/original art produced by a deterministic drawing pipeline --
not copied or downloaded from any commercial game or reference image. See
"Replacing with licensed/hand-drawn art" at the bottom for how to retire
it later without touching gameplay code.

## Tile dimensions

- World tile grid: **32x32 px**, matching `PixelAtlasMap.TILE_SIZE`.
- `ArenaBuilder`'s existing world-space scale (arena half-size, block
  size, road width) is unchanged -- tiles are laid out *within* that
  existing coordinate system, they don't rescale it.

## Actor frame dimensions

- Player / Survivor / Zombie frames: **32x40 px** (`PixelAtlasMap.ACTOR_FRAME_SIZE`),
  the extra 8px of height over a tile giving a human silhouette room above
  the feet without changing collision shapes (still circles matching each
  actor's existing `CollisionShape2D` radius).
- 2 animation frames per variant: `idle`, `walk` (a single alternate-frame
  shuffle/bob, not a multi-frame walk cycle) -- see "Known simplifications".
- Facing is presented via horizontal flip (`flip_h`) driven by the
  parent `CharacterBody2D.velocity.x` sign, not a rotated/8-directional
  sprite -- consistent with the existing gameplay convention that actor
  *bodies* don't rotate (only `WeaponPivot` does, for aim).

## Color palette

Approximately 34 principal colors, defined once in
`tools/generate_pixel_assets.gd::PALETTE` and reused by every generator
function (ground, buildings, props, actors, effects, UI) so the whole
game reads as one coherent set rather than per-asset one-off colors.
Grouped by role: asphalt/road, sidewalk/curb, grass/dirt/concrete, four
roof material variants (+ dark trim shade each), safehouse
floor/wall/barricade, a single shared outline color, actor skin/clothing
bases, blood, the four storage item-category colors (food/water/
materials/medical), and UI panel/border/bar colors. Daylight presentation:
no directional light-source shading is modeled -- colors are chosen
bright/mid-value rather than gradient-lit, matching a flat daylight look.

## Outline rules

- One shared dark outline color (`PALETTE.outline`, near-black with a
  slight warm tint) is used on every actor sprite, prop, and UI panel
  border -- never a different outline hue per asset.
- Outlines are drawn as a 1px border on prop/UI edges and as a 1px
  silhouette edge on actor sprites, always at full opacity (no
  anti-aliased/blended edge pixels, to stay crisp at nearest-neighbor
  filtering).

## Shadow rules

- Actors: one shared `assets/pixel/actors/shadow.png` (a soft dark
  ellipse, semi-transparent), one `Sprite2D` instance per actor, drawn
  beneath the body sprite (lower z / earlier in the "actors" tree order),
  offset slightly down and never rotating or resizing with movement.
- World props/buildings do not cast separate drop shadows -- rooftop
  edge-tile shading (a darker trim color on N/S/E/W edges) stands in for
  directional shadow without per-object shadow nodes.
- No dynamic 2D lights (`PointLight2D`/`DirectionalLight2D`) anywhere;
  "shadow" is always a pre-drawn sprite or a darker palette tone baked
  into a tile, never computed at runtime.

## Layer order (z-index / draw order, back to front)

1. `Ground` (grass / dirt / cracked concrete / bare pavement fill)
2. `Roads` (asphalt variants)
3. `Sidewalks` (sidewalk + curb tiles)
4. `RoadMarkings` (crosswalk / dashed / solid lane lines)
5. World decals (persistent blood-decal sprites -- above ground, below actors)
6. Actor shadows
7. Actors (player / survivors / zombies) -- individually y-sorted is not
   used in this slice (top-down with a fixed small height offset is
   readable enough at this scale); draw order among actors follows scene
   tree order, not per-frame sorting.
8. Props (crates, lamps, hydrants, barricades, loot/world-drop sprites)
9. `BuildingRoofs` (roof tiles + rooftop detail sprites -- drawn above
   street-level actors/props so a building reads as "taller", matching
   the previous primitive build's `Polygon2D` buildings already drawing
   above the road)
10. `Overlays` (reserved for future UI-adjacent world overlays; currently
    unused, kept as an explicit empty layer per the layer list below so
    later work has a defined place to attach)
11. UI (CanvasLayer, always on top, unaffected by world z-index)

Buildings' **collision** stays exactly where it was (a `StaticBody2D`
child of `World/Buildings`, unchanged rectangle matching the footprint) --
only the *visual* roof moved onto the `BuildingRoofs` `TileMapLayer`.

## UI scale

- Native viewport stays **1280x720**; UI continues to use the existing
  `canvas_items` + `expand` stretch mode, unchanged.
- Icons are 16x16px pixel art (`assets/pixel/ui/*.png`), displayed at 1x
  (no upscale blur) inside existing `HBoxContainer`/`VBoxContainer` rows.
- Panel backgrounds and button states are flat-color `StyleBoxFlat`
  resources (dark, semi-opaque, light 2px pixel border) defined in
  `resources/theme/pixel_theme.tres` -- deliberately not a stretched
  texture, so there is zero risk of sub-pixel/blur artifacts on panel
  edges regardless of window scale.
- Font: Godot's built-in default font (no external/unlicensed font
  file), with a black outline (`outline_size = 2`) and a 1px drop shadow
  configured entirely inside the Theme resource -- see "Replacing with
  licensed/hand-drawn art" below for how to swap in a licensed pixel font
  later without touching any scene.

## Naming conventions

- Atlas tile names: `snake_case`, grouped by prefix -- `asphalt_*`,
  `sidewalk_*`, `curb_*`, `road_*`, `grass`/`dirt`/`concrete`/
  `cracked_ground`, `roofA_*`/`roofB_*`/`roofC_*`/`roofD_*` (material
  variant letter + `_center`/`_edge_<dir>`/`_corner_<dir>`), `safehouse_*`.
  The full list lives in `scripts/visuals/pixel_atlas_map.gd::ENV_TILES`
  (the single source of truth both the generator and every consumer read
  from -- never hard-code a tile's atlas column/row anywhere else).
- Prop/effect/UI files: `assets/pixel/<category>/<name>.png`, one file
  per sprite (e.g. `assets/pixel/props/crate.png`,
  `assets/pixel/effects/muzzle_flash.png`).
- Actor atlases: `assets/pixel/actors/<player|survivor|zombie>_atlas.png`,
  one row per palette variant, one column per animation frame (`idle`,
  `walk`) -- see `ActorSpriteLibrary` for the exact frame table.

## Asset replacement instructions (for later hand-drawn/commercial art)

Every generated asset is referenced *only* by `res://` path (through
`PixelAtlasMap`, `ActorSpriteLibrary`, or a direct `preload()`/`load()`
in a scene/script) -- nothing depends on the generator having produced
that exact file's pixel content, only its path, dimensions, and (for the
environment atlas and actor atlases) cell layout. To replace with
licensed or hand-drawn art:

1. Overwrite the PNG(s) at the same `res://assets/pixel/...` path(s),
   keeping the same tile/cell grid (32x32 for environment tiles, 32x40
   per actor frame, one row per variant / one column per animation).
2. For UI, swap `resources/theme/pixel_theme.tres`'s font resource
   (currently the built-in default) for a licensed pixel font file, and
   optionally swap the flat `StyleBoxFlat` panels for `StyleBoxTexture`
   pointing at new 9-slice panel art -- both are isolated to that one
   Theme resource.
3. `tools/generate_pixel_assets.gd` itself never needs to run again once
   replaced; it is only the *placeholder* pipeline, not a build
   dependency of the game.

## Known simplifications (Phase 3A scope)

- Two animation frames (`idle`/`walk`) per actor variant, not a
  multi-frame walk cycle -- kept intentionally cheap for up to 250
  concurrent zombies. (Superseded for actor animation specifically by
  Phase 3A.1's directional multi-frame system below; the two-frame note
  is preserved here as the original Phase 3A baseline.)
- Actor facing is a horizontal flip, not full 8-directional sprites.
  (Also superseded by Phase 3A.1's directional animation, which adds
  down/up/side frame sets.)
- Persistent blood decals are capped and recycled (see
  `scripts/combat/blood_decal_manager.gd`), not per-hit particles.

## Phase 3B additions -- building and street art

Extends the same deterministic generator (`tools/generate_pixel_assets.gd`)
and the same rules above (nearest-neighbor import, shared `PALETTE`,
isolated cosmetic RNG via `CosmeticRng`, one shared `TileSet`/atlas) --
nothing about the art pipeline itself changed, only its coverage.

New environment-atlas floor tiles (`PixelAtlasMap.ENV_TILE_NAMES`):
`floor_restaurant`, `floor_kitchen`, `floor_store`, `floor_clinic`,
`floor_interior_plain`. New standalone prop/building sprites under
`assets/pixel/props/`: exterior wall variants (`wall_brick`,
`wall_concrete`, `wall_plaster`, `wall_shopfront`, each with a `_dark`
trim shade) and one shared `wall_interior`; door states
(`door_closed`/`door_open`); window states (`window_intact`/
`window_boarded`); furniture (`table`, `chair`, `counter`, `shelf`,
`fridge`, `medical_cabinet`, `bench`); street objects (`utility_box`,
`street_sign`, `street_lamp`, `hydrant`, `car_sedan`, `car_wreck`,
`tree`, `planter`, `dumpster`, `trash_bag`, `road_barrier`, `cone`). All
drawn by dedicated `_draw_*` functions in the generator, reusing the
existing `PALETTE` (extended with matching entries, e.g.
`wall_brick`/`wall_brick_dark`) rather than introducing a parallel color
set.

**Known gaps against the full Phase 3B art request:** van/truck, bicycles,
vending machines, shopping carts, restaurant-specific signage,
apartment/workshop fixtures (couches, office desks, toilets/sinks, kitchen
equipment beyond the restaurant's own), and building-specific roof
elements beyond the shared 4-letter roof-material system were not
generated this pass -- see the Phase 3B completion report for the full
deferred-art list.

## Phase 3B.1 -- Apartment01 / Workshop01 art reuse

No new sprites were generated for the two new building archetypes; both
furnish their rooms entirely from existing Phase 3A/3B assets rather than
widening the generator's coverage further. Apartment01's bedroom reuses
`assets/pixel/props/bed.png` (originally the Phase 3A safehouse sleep
spot) and its living-room/kitchen dresser reuses
`assets/pixel/props/medical_cabinet.png` as a plain storage-stand-in.
Workshop01's loading bay and storage room reuse
`assets/pixel/props/crate.png` and `assets/pixel/props/pallet.png`
(originally the safehouse's own storage art). This keeps both new
buildings' known-gaps list from the table above unchanged -- dedicated
apartment/workshop fixtures are still deferred, not added this pass.
